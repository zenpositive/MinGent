MinGent - what changed
======================

Version 1.7.0
- MinGent now behaves the same whatever the Windows display language and
  regional format are. On a Turkish or Azeri Windows, checks that ignore
  upper and lower case could miss a command with a capital I in it, such
  as Invoke-WebRequest or Remove-Item, so Auto did not ask where it
  should have. And in languages where two letters can count as one (cs
  in Hungarian, ch in Czech, aa in Danish), Windows answers that a word
  like csv does not start with c. Inside MinGent, numbers, dates and
  comparisons of text now use one fixed format on every PC. What you
  read still follows your Windows settings: the grouping of large
  counts, search in your chats, the numbers of a copied chart and the
  paper size of new documents.
- Settings > Safety: the switches under "What Auto asks about" can be
  changed with "Your own choice" only. With Risky steps or Most steps
  picked they are dimmed and show what that level asks about. Your own
  switches are kept apart, so trying another level no longer overwrites
  them, and Your own choice stays picked even when your switches match
  one of the levels. Before, picking a level set the switches, and
  picking Your own choice afterwards brought nothing back.
- Auto: renaming a file outside the work folder asks first, as deleting,
  replacing and moving do. This covers Rename-Item and ren, also when
  the files come from an earlier command through a pipe.
- Auto: copying files to another computer with scp, pscp or rsync,
  uploading with aws, az, gsutil, gcloud storage or rclone, and putting
  a site online with vercel, netlify, firebase, wrangler or gh-pages
  count as uploading and ask first. Downloads with the same tools run as
  before.
- Browser console: on a website, code that takes a property of document,
  window, navigator, location or history through a computed name is
  refused, like other code that hides what it runs. So is code that
  keeps the name of a cookie, of saved data or of a form field's value
  in a variable, or lists it for JSON.stringify. Before, const k =
  'cookie'; document[k] ran without a question in Auto.
- Browser console: filling a map with m[a.href] = ... is no longer taken
  for changing a link, so such code reads the page without a question
  again.
- Checking a JSON file the agent writes no longer takes long when the
  file has thousands of blank lines, and neither does showing a reply
  that holds a link with thousands of spaces or tabs in its address.
- A path with characters Windows does not allow, a time with hundreds of
  digits and a Word heading style with an unusual digit come back to the
  agent as plain errors it can act on.

Version 1.6.0
- Gemini web: the usage icon's weekly bar shows your weekly use. MinGent
  read the usage from the reply behind Gemini's chat badge, which holds
  only the fuller of the two limits, so the other bar stayed at 0. It now
  reads the reply behind Gemini's Usage limits page, which lists both.
- Gemini web: clicking the usage icon opens its details, as clicking the
  context ring does: a bar for the 5-hour and the weekly limit, how much
  of each is used, when each resets and how old the reading is.
- Build-MinGent.bat says less and only what's true now. The option to
  build with your own icon (an icon.png next to it) is gone, and so is
  the note about a "C# 5" compiler message that no longer shows.
- Programs: a click, drag, scroll or hover at a position in a program now
  checks which window is really at that spot first. If another window is
  in front of it, such as a notification or a window that stays on top,
  nothing is sent and the agent is told why. Before, only clicks on a
  control were checked, so a click at a position could land in the other
  window.
- Programs: positions from a screenshot are no longer used after the
  window changed size, since they would point at other parts of it. The
  agent is asked to take a new screenshot first.
- Programs: the agent now sees the buttons, menus, lists and text of
  Windows 11 apps built with WinUI, such as Paint. Before, Paint's window
  looked empty to it, so it had to work from screenshots and guess where
  to click.
- Programs: when a click opens a drop-down or pop-up in such an app, the
  agent sees its contents right away, as it does with menus.
- Programs: when a menu, drop-down or other pop-up that closes on a click
  outside it is still open and the agent clicks, drags or types somewhere
  else in the program, MinGent closes it first. Such a click only closes
  the pop-up, so in Paint the agent's click on a color did nothing and it
  kept trying. Pop-ups that stay open, such as Paint's text toolbar, are
  left alone.
- Programs: a control picked by its ref is used in the window the ref
  came from, even when the agent names another window. Before, the step
  failed and had to be repeated.
- Programs: typing into a box that takes both typed text and picks from
  a list, such as the font size in Paint, replaces what the box held, as
  in other one-line fields. Before, the new text went after the old, so
  48 typed over 11 became 1148. The agent also sees which such boxes it
  can type into.
- Programs: clicks and drags move the mouse the way a real mouse does.
  In Paint, the first drag after picking a tool or a color drew nothing,
  because the app never saw the pointer arrive.
- Programs: many programs reopen your documents or tabs when they start,
  as Notepad does. The agent is told to make a new document or tab for its
  work there and to leave yours as they are.
- Programs: a program whose main window is a dialog, such as Character
  Map, now also goes next to MinGent, as other programs do. So does a
  program whose main window belongs to a hidden window of its own.
- Programs: when something the agent does makes the program go full
  screen, MinGent puts it back on its half of the screen, next to
  MinGent, so you can keep following along.
- Some model servers lose number arguments, such as where to click, on
  the way to MinGent. When that happens, MinGent switches the chat's tools
  to take numbers as text, so the next try works. Before, the agent sent
  the same click again and again until MinGent stopped it.
- Browser: when a click opens a page dialog, the agent can answer
  Cancel, or type the text a prompt asks for. Before, MinGent always
  answered OK and left prompts empty, so a page that asked for text never
  got any.
- Browser: code the agent runs on a page gives back lists and objects in
  full. Before, a list of objects came back as "Array(3) [Object, Object,
  Object]" and the agent had to run the code again.
- Reading an Excel file tells the agent what each column holds: text,
  numbers, dates, percentages or formulas. To check that a workbook it
  made has real dates and numbers, the agent took the file apart with
  commands, and each one needed your OK.
- MinGent goes back to its own size when you start a new chat or open
  another one, once no chat is working. Before, it stayed at half the
  screen as long as the program the agent had used was open.
- The question before the agent opens a program says how long the
  permission lasts: until the program closes. It said "Until this chat
  ends", but the program stays usable after that.
- Commands: reading back a Word, PDF, Excel or PowerPoint file the agent
  made in the same chat no longer makes its later commands wait for your
  OK. When a file the agent didn't write does, the question now says it
  read a file, instead of "web content".
- Commands: after the agent read a web page or a program's window,
  PowerShell commands that only read no longer ask first, also short
  scripts with variables, loops and filters, such as counting the rows of
  a file it downloaded. Commands that change something, run code, reach
  the internet or touch keys and passwords still ask, and so does reading
  many files outside the work folder at once.
- Commands: a folder written as $env:USERPROFILE, $HOME or ~ is judged
  like the same folder written out. Listing your Downloads to check on a
  file asked after the agent had read a web page, though the same command
  with the full path did not. Keys, passwords and app data still ask.
- Auto: the switch under the message box is just Auto on or off. How
  careful Auto is, you pick in Settings > Safety under "Auto asks before":
  Risky steps (the new default), Most steps, your own choice, or Nothing,
  which is Full auto. Full auto left the menu next to the switch; it still
  warns you first and turns back into your Auto choice when MinGent closes.
- Auto with Risky steps opens and uses programs and saves downloads
  without asking, the kinds of question it asked most. Choose Most steps in
  Settings > Safety to keep the old questions.
- Auto: after the agent read a program's window, it no longer asks before
  clicking and typing on in that same program, or in a program you allowed
  in the chat. Text from the web, a file or another program still makes
  it ask first, and so does a file dialog, which can save anywhere.
- Auto: files a page downloads, such as PDFs and pictures, no longer ask
  first after the agent read the page. Programs, scripts and archives still
  ask.
- Safety: when the agent reads a password, key or token in a file, a
  command's output or a program's window, MinGent now asks before that
  value goes into a web address, a search or a field on a website, also
  when it is short. Pages on this PC, such as a site being built, are not
  asked about.
- Safety: after the agent read web content, a risky question now says so,
  also in Ask mode, and code for a page on this PC can no longer be allowed
  for the whole chat.
- Safety: after the agent read web content, changing a file inside a
  project's .git folder asks first. Git runs the hooks and settings kept
  there without showing them, so a page could have used them to run
  something later. Git commands work as before.
- Auto runs code in a web page that only reads the page without asking.
  Code that changes the page, sends something or reads cookies, saved
  data or form fields still asks.
- Browser: on a page that loads more as you scroll, such as a feed, the
  agent is told when more loaded and how long the page is now. Before,
  every scroll at the bottom said the same thing, so the agent couldn't
  tell that anything new had come and ran page code to count instead.
- Browser: when a site asks about cookies, the agent turns down the
  optional ones unless you tell it otherwise. Before, it often accepted
  them all to get the question out of the way.
- Browser: things a page lets you drag, such as cards, boxes or list
  items, get refs, so the agent can drag them by ref. So do sortable
  column headings and places that react to a right-click or double-click.
  Before, the agent had to find them on a screenshot, which a model
  without vision can't do.
- Browser: a drag and drop that changed the page is reported as taken.
  Before, a page that handled the drop without saying so was reported as
  not handling it, and the agent took a screenshot to check.
- Browser: parts of a page built from web components are read as they
  show on screen. Before, the agent also saw their hidden placeholder
  text, such as a default title, and some of their text out of order.
- Browser: parts of a page that come from another site, such as an
  embedded form, editor, sign-in button or cookie question, are read with
  the rest of the page, and the agent clicks, types, picks and gives
  files in them by ref. Before, it only saw that such a part was there
  and could reach it only by position in a screenshot, which a model
  without vision can't do, and typing into one asked you every time.
  Payment and CAPTCHA boxes from other sites still ask.
- Browser: a dialog, cookie question or other box that sits on top of
  a page is read first. Before, it came where it sits in the page's
  code, on a long page often at the very end, so the agent had to read
  on or take a screenshot to find what was in the way.
- Browser: long links, headlines and boxes you can click are shown
  whole, text typed into an editor is read back line by line with its
  headings and lists, and a text area shows what it holds. Before, each
  was cut after 80 or 120 characters, so the agent ran page code or took
  a screenshot to read the rest.
- Browser: a link that starts a download no longer comes back as "the
  page could not be opened". When the download began a moment after the
  click, the agent got that error and the file was dropped. MinGent now
  waits for it, and a download that shows up after a step is dealt with
  at the next one.
- Browser: the agent can click words on a page that have no ref, such
  as a plain "Close" that only reacts through the page's code or a table
  heading that sorts, by giving the words. Before, that took a position
  from a screenshot, which a model without vision can't get.
- Browser: items inside other items, such as the entries of a submenu,
  the files in a folder tree or the close button of a tab, get refs of
  their own, and so do pictures. Before, only the outer item was listed,
  named after everything inside it, and a picture could only be hovered
  or clicked by position.
- Browser: a drop-down, slider or text box built by the page itself
  shows what it holds, as the built-in kinds do, and a button whose
  spoken label differs from its words shows both. Before, the agent saw
  only the label, so it could not tell what a custom drop-down was set to.
- Browser: buttons and menus whose label is drawn by the page's style
  sheet, such as the heading menu of a text editor, are listed with that
  label. Before, they had no name, so the agent had to open each one or
  look at a screenshot.
- Browser: a part of the page that is still empty is listed as having
  nothing in it yet, so the agent waits for it instead of taking it for
  an empty box.
- Browser and programs: the agent can wait a few seconds before reading
  a page or a program that is still loading. Before, it ran a sleep
  command to wait, which needed your OK once it had read a web page or a
  program's window.
- Programs: rows of a list with columns, such as in System Information,
  come with the text of their other columns. Before, the agent saw only
  the first column and had to read the rest from screenshots.
- Programs: the list of programs the agent can open says that one
  missing from it is most likely not installed, so the agent tells you
  instead of trying other ways to start it.
- Programs: tooltips and other pop-ups of Windows apps such as
  Calculator are read, and a hover shows the tooltip right away. Before,
  such a pop-up looked empty, so the agent read tooltips from screenshots,
  and reading the pop-up made it read the window behind it again.

Version 1.5.0
- Gemini web: when Gemini answers with another model than the one you
  picked, the chat says which one, and says so again when your model is
  back. Google can do this near the usage limit or when a model is busy.
- Gemini web: a model that thinks for a long time, such as Gemini 4 Argon,
  now gets up to 10 minutes. Before, MinGent stopped waiting after 4
  minutes and quietly sent the request again, up to 4 times, so a long
  think could look like it never ended. While it waits, the status line
  says how long the model has been thinking, and when it stops waiting it
  says so in the chat.
- Gemini web: the model menu shows the models your Gemini plan includes,
  as Gemini's own menu does. Gemini also lists models from higher plans,
  such as 4 Carbon on a Pro plan, and MinGent showed those too.
- Gemini web: a chat waiting while another chat or a helper uses Gemini
  now says so, instead of seeming to think.
- Gemini web: an icon next to the context ring shows how much of Gemini's
  usage limits you have used: two small bars for the 5-hour and the weekly
  limit, and the higher percentage. Hovering it shows when each one resets.
  The notice about another model answering, and the message when a limit
  is reached, say the same.
- Watching a video file on this PC works. The built-in browser reported
  every video file as "could not be opened" even while it showed the
  video, so the agent gave up on it.
- The final answer is the only text you need to read: everything the agent
  writes while it works stays in the steps. A longer text no longer stays
  in the open once the next step starts.
- When a model wrote its answer next to its last step and then only said
  it was done, the steps showed a "Done." that wasn't the end, MinGent asked
  the model again, and the answer could show up twice. Now that answer
  becomes the final answer, and the model isn't asked again.
- When a model clicks without saying where, the error now says what it
  sent, so it can correct the call instead of repeating it.
- Watching a short video, or moments less than a second apart, showed
  the same time on two pictures (0:10, 0:10, 0:12, 0:12). Each picture now
  has its own time, with tenths of a second where whole seconds can't tell
  them apart.
- On a page the agent made or changed in the same task, a button whose
  label sounds like paying, such as "Delete: Buy milk" on a to-do list it
  built, no longer asks for your OK. Payment boxes from other sites inside
  such a page still ask.
- A command that named a path with spaces in quotes, such as a file in the
  chat's own folder, could be called "outside the work folder" and ask in
  Auto mode. The whole path is checked now.
- When a run was stopped or ended without an answer, a short note the agent
  wrote on the way ("...I'll write the story now.") could show as if it
  were the answer. It stays inside the steps now.
- The line that sums up the steps counts what happened: code run in a web
  page's console is browser use, not commands; showing a file in Notes is
  not reading it; steps in a program name the program ("Used Calculator");
  new files count as created, not edited, and patches as edited files;
  saving to memory or scheduling a task is named first instead of counted
  as "other steps"; and a step that failed, such as an edit that didn't
  apply or a page that couldn't be read, is no longer counted as done.
- A Word, PowerPoint or PDF file that used the same picture twice gave
  both the second one's caption. Each keeps its own now, and the picture is
  still stored once.
- Percentages in Excel workbooks the agent reads show as they do in Excel
  (27.5%), not as the number behind them (0.275).
- The agent was told its work folder as "<folder> (this chat's own
  folder)". Chat folders are named after the first message, so a model
  could take the note for part of the folder's name and use a path that
  doesn't exist, in commands and in its answer. The note now comes before
  the path.
- A chart's axis mixed units, such as 5000 next to 10K and 15K, or 500K
  next to 1M. Every number on an axis now uses the same unit.
- In a temporary chat, or with memory switched off, the agent is now told
  so. Asked to remember something, it says memory is off instead of
  looking for another place to keep it, such as MinGent's own memory file.
- When the agent asks to read a file in MinGent's Data folder, the question
  now says what the folder holds: chats, memory, settings with saved API
  keys and the browser's sign-ins.
- Fewer questions for work on pages from files on this PC. Such a page now
  counts as web content only when it loads something from the web (pictures,
  data, frames, live connections) or sits in Downloads or a temporary folder,
  the same rule as reading the file itself. Before, testing a page the agent
  had just built in the browser made Auto ask before every later command and
  download. In Auto, console code on such a page no longer asks either,
  unless the chat has read web content.
- When the agent opens a program or you allow it to use one, MinGent and the
  program go side by side right away. Before, that waited for the agent's
  next step in the program.
- Clicking a drop-down list in a page opened a menu outside the page that
  the agent can't see, so it guessed with key presses. It is now told to
  pick the option with browser_type, which also sets sliders and date
  fields in one step.
- A button on a web page that shows only an icon, such as a close X, a
  bin or a magnifying glass, and has no label of its own, is now named
  after its icon ("icon: close"). Before, the agent saw a row of buttons
  without names and had to guess which one closes or deletes.
- With a model that can't see pictures, reading a program's window now
  says where each control and the large areas of the window are, so the
  agent can click and drag by position, for example to draw in Paint. Such
  a model had no way to point at anything without a name. The program and
  browser tools also no longer tell it to take screenshots, which it can't;
  when it asks for one anyway, it is told why there is none and what reads
  the window or page instead.
- A link meant to open in a new tab on a page from this PC was blocked. It
  opens in the browser pane, as links on websites already did.
- After Undo, the agent is told which files went back and which went to
  the Recycle Bin. Before, it went on from the undone version: asked about a
  change you had just undone, it described it as still there.
- Undo reloads the browser pane when it shows a page the undo changed back,
  so the page matches its files again. Before, it kept showing the undone
  version until you reloaded it.
- A scheduled task could work in a chat's own folder, and deleting that
  chat deleted the folder, so the task stopped running. The folder now
  stays while a task works in it, and the delete question says so. A task
  set up from a chat that hasn't made any files gets its own folder.
- A new chat no longer starts with an empty browser pane. When the agent
  had opened the pane, it stayed open and blank after a new chat, another
  chat or a temporary chat began, and took room from the chat, most of all
  with MinGent beside a program. It now closes unless you have been using
  it. A chat started while another one works no longer opens a blank pane
  either, and going back to a chat shows its pane only if it was open there.
- The agent could not close a browser pane it had opened itself: when it
  was the first use of the browser since MinGent started, or after the
  chat had worked in the background, it was told you had opened the pane,
  so the pane stayed.
- When the account with a model's provider is out of credit, such as
  DeepSeek's "Insufficient Balance", the chat now says so and what to do
  about it, instead of only "The model returned an error".
- When a provider's content filter refuses a request, such as DeepSeek's
  "Content Exists Risk", the chat says so and its button starts a new chat,
  since asking again in the same chat meets the same filter. MinGent no
  longer sends such a request a second time, nor one refused for lack of
  credit. The message that a conversation is too long for the model gets
  the New chat button too, in place of "Try again".
- Typing into a program's field that already held text put the new text
  where the click landed, in the middle of the field: a box that kept the
  last search, such as Notepad's Find, ended up with both mixed together.
  The typed text now replaces what a one-line field holds and goes at the
  end of a larger text area, and the agent can choose the other way. The
  same goes for a box you can type into or pick from, such as a font size:
  "24" no longer turns 11 into 1124.
- Reading a program's window showed only the first 100 characters of a
  text field, so the agent couldn't read a document open in a program, or
  check what it had written there, unless it could take a screenshot.
  app_read now shows the whole text of a long field, with its lines, up to
  4,000 characters a field.
- The agent can read a PDF, Word, Excel or PowerPoint file on the web,
  such as a paper on arXiv or a report a site links to. web_fetch said "it
  is not a text page" for them, and the browser shows a PDF in a viewer
  whose text can't be read from the page, so asked to sum up a PDF from a
  link, the agent couldn't. Reading a PDF open in the browser now gives its
  text too, also one behind the site's sign-in.
- web_fetch also reads YAML and TOML files, and a text file a server sends
  without a type, such as a Markdown file in cloud storage. With a model
  that can see pictures, a link to a picture shows the picture. It called
  all of these "not a text page".
- A right-click menu, or another menu a program opens, now comes back with
  the click that opened it, with its items for the agent to click or Escape
  to close it. Before, the agent saw only the window under the menu, so it
  couldn't pick anything from a right-click menu.
- When a step in a program opens another window next to the one the agent
  works in, such as a colour palette that drops down from a toolbar or a
  new document window, the step says so and names the window, so the agent
  can read it. Before, it didn't know the window was there.
- A link to a file in the agent's answer works when the path has spaces,
  as every chat's own folder does ("Files\Plan a trip\..."). Before, the
  link stopped at the first space, so clicking it did nothing. A link to a
  folder now opens the folder, a picture opens larger, a file Notes can't
  show opens its folder, and a file that is gone says so. The agent now
  links the files it made or changed in its answer, so they open with a
  click.
- The agent can read all of a long page in the browser, such as a long
  article or a thread behind a sign-in, part by part. Before, it got only
  the start: the page was cut and it was told to scroll, which didn't
  change what it read.
- Searching the chat list finds chats by what you and the agent wrote in
  them, not only by their titles. Opening a chat from the search scrolls
  to the first place the words come up and selects them, also in the
  agent's steps.
- An answer with a table has "Copy the table" in its right-click menu. The
  table pastes as a table into Excel, Word or Google Sheets, instead of as
  Markdown text in a single column.
- In a program's list with more items than the agent is shown at once,
  such as a long playlist or file list, reading the window after scrolling
  now lists the items in view. Before, it always listed the first items, so
  the agent couldn't reach the rest by scrolling.
- Clicking an item in a program's list or tree, such as a file, a song or
  a folder in a file dialog's side pane, now clicks it once where it is.
  Before, MinGent used the item's own default action, which for many lists
  is a double-click, so the item opened, and for folders it only folded
  them open or shut.
- A click, drag or hover aimed at a control that is out of view in a
  program, such as a field further down a long form, went to whatever else
  was at that place on the screen. The agent is now told to scroll it into
  view first. Typing into such a field still works when the field takes
  the keyboard focus, and a control half in view is clicked where it shows.
- Clicking a button that is greyed out, such as Next before a form is
  filled in, did nothing without a word, in a program or on a web page,
  and neither did typing into a greyed-out field. The agent is now told
  the control is disabled and that the program or page wants something
  else first.
- The agent can read and search a file another program is still writing,
  such as a server's or a game's log. Windows refused it as "being used by
  another process", so the agent couldn't look at the log of something
  running.
- Reading a program with a big window, such as a music player or a chat
  app, could leave out controls without saying so, most often the ones at
  the bottom, like a player's play button. MinGent stopped after a fixed
  number of elements, and many of them were empty frames. Now only controls
  and labels count, the ones in view are listed first, and the agent is
  told when there are more, which app_read lists with part=2.
- A program window that shows no controls the first time it is read, such
  as one still starting or one built on web pages that makes its controls
  only once something asks for them, is read again a moment later, and a
  start-up screen that closed in the meantime is reported as closed. Before,
  the agent was told right away that the program has no controls it can
  read, and fell back on screenshots.
- Opening a program that shows a start-up screen first, such as an office
  program or a game launcher, hands the agent the main window once it is
  up, and that window goes side by side with MinGent. Before, the agent got
  the start-up screen, which closed a moment later.
- When a program stops responding for a while, for example while it saves
  or exports, reading it or taking its screenshot waits up to 15 seconds
  for it to answer, and then says it is still busy. Before, reading it took
  up to 9 seconds and then said the program has no controls the agent can
  read, and the agent ran commands just to wait, each asking for your OK.
- Looking at the whole screen while a program was busy left that program
  out and said none of the agent's windows was on the screen. The busy
  window now shows as a marked blank box, and the agent is told why.
- A minimized program window is brought back when the agent reads it,
  without taking the keyboard from what you are doing. Before, the agent
  saw a tiny window far off the screen, every control in it counted as
  out of view, and clicks on it were refused for that reason.
- Putting a minimized or maximized program next to MinGent, which happens
  at the agent's first step in it for each request, no longer makes that
  program the active window. Before, typing meant for MinGent could land
  in the program.
- A click or typing in a program finds the control where it is at that
  moment. Before, a control that moved after the agent read the window,
  such as a file in a dialog that was still loading, was looked for where

Version 1.0 beta - first public release

Known limits in this beta
- Offline mode stops MinGent's own connections; it is not a firewall, so a
  program that goes online by itself still can.
- YouTube transcripts come from YouTube's own pages and can stop working
  when YouTube changes them.
- Letting the agent try CAPTCHAs (Settings > Agent) is an experiment and is
  off by default.
- The agent controls only programs it started itself (and ones Windows opens
  for its commands); everything else on your PC stays off limits.
